DATA TRAVELS IN PACKETS

Data sent over a network is not sent as one big block. It is broken into small units called packets.

Big message

Receiver

What is a packet?

Answer: a small unit of data. Data sent over a network is broken into packets.
Packets | Inside a packet

THE STRUCTURE OF A PACKET

Every packet has three parts: a header, a payload and a trailer. Tap each part.

Name the three items in a packet header.

Answer: the destination address, the packet number and the originator’s address.
Packets | Packet switching

PACKET SWITCHING

Watch the packets travel across the network.

Why do the packets need numbers?

Answer: they can arrive in a different order. The receiving device uses the packet numbers to put them back in the correct order.
Packets | Packet switching steps

PACKET SWITCHING: THE STEPS

1

The data is broken into packets.

2

Each packet gets a header with the destination address, packet number and originator’s address.

3

A router sends each packet along a route. Packets can take different routes.

4

The packets may arrive in a different order.

5

The receiving device uses the packet numbers to put them in order.

6

The message is put together again.

Packets | Routers

THE ROLE OF A ROUTER

A router receives a packet, reads its destination address and sends it on towards the destination.

Why can two packets from the same message take different routes?

Answer: each router chooses the route for each packet separately, so packets can use different routes (for example, to avoid a busy part of the network).

What can happen when packets take different routes?

Answer: they may arrive in a different order. The packet numbers are used to reorder them.

CHECK YOURSELF: PACKETS

Answer: header, payload and trailer.

2 What is the payload?

Answer: the actual data being sent in the packet.

3 What does a router do?

Answer: it reads the destination address in the header and sends the packet on its way.

4 What does the receiving device do with the packet numbers?

Answer: it uses them to put the packets in the correct order and rebuild the message.

Direction | Part A — Quick review

SERIAL TRANSMISSION

  • Data is transmitted using a single wire.
  • Each bit is transmitted one at a time.

The bits travel in sequence.

Direction | Part A — Serial advantages

SERIAL — ADVANTAGES

Because data is sent one bit at a time:
  • Bits should arrive in sequence.
  • Less chance of data skewing.
Because only one wire is used:
  • Less chance of interference.
  • Less chance of errors.
  • The cable is cheaper to manufacture and buy.

Serial is therefore more suitable for long distances.

Direction | Part A — Serial limitations

SERIAL — DISADVANTAGES

Because only one bit is sent at a time: transmission is slower.

Additional information may also be needed to tell the receiving device when transmission starts and stops:

START BIT

transmission starts

→
DATA BITS

1 0 1 1 0

→
STOP BIT

transmission stops

Direction | Part A — Parallel transmission

PARALLEL TRANSMISSION

  • Data is transmitted using multiple wires.
  • Multiple bits are transmitted at the same time.
Direction | Part A — Parallel advantages

PARALLEL — ADVANTAGES

  • Multiple bits are sent at the same time, so transmission is quicker.
  • Many computers and devices also use parallel transmission to transmit data internally.
Direction | Part A — Parallel limitations

PARALLEL — DISADVANTAGES

  • Bits may not arrive in the correct order.
  • They may need to be reordered.
  • More chance of data skewing.
  • More wires give more chance of interference.
  • More chance of errors.
  • The cable is more expensive.

Parallel is therefore more suitable for shorter distances — often limited to approximately 5 metres.

Part B — Direction of data

NOW THINK ABOUT DIRECTION

Direction | Simplex

SIMPLEX TRANSMISSION

Data is transmitted in ONE direction only. There is no data transmission in the opposite direction.

Real-life example (Coursebook): Keyboard → Computer. The keyboard sends data to the computer. The computer does not need to send data back to the keyboard as part of this transmission method.
Direction | Simplex: think about it

WHY SIMPLEX?

Imagine pressing A on a keyboard. The key information needs to travel Keyboard → Computer, so the computer can process the key pressed.

Why would a simplex connection be suitable? (tap)
The data only needs to go one way — from the keyboard to the computer. Nothing needs to be sent back.
Direction | Half-duplex

HALF-DUPLEX TRANSMISSION

Data can travel in both directions, BUT only ONE direction at a time.

If data is travelling A → B, data cannot travel B → A at the same time.

Direction | Real-life example: Wi-Fi

HALF-DUPLEX AND WI-FI

Both directions are possible, but not at the same time.

Direction | Half-duplex: when is it suitable?

WHEN WOULD WE USE HALF-DUPLEX?

Half-duplex is suitable when:
  • Data needs to travel in both directions.
  • There is no requirement for both directions at the same time.
Coursebook note:

Two half-duplex connections can be set up using two different communication channels to allow data to travel in both directions at the same time.

Direction | Full-duplex

FULL-DUPLEX TRANSMISSION

Data can travel in BOTH DIRECTIONS AT THE SAME TIME.

Data can be sent A → B while data is also being sent B → A.

Direction | Real-life example: telephone

FULL-DUPLEX IN REAL LIFE

Person A can speak to Person B. At the same time, Person B can speak to Person A.

Full-duplex suits situations where data must be sent and received simultaneously.

Errors | Cambridge IGCSE / O Level Computer Science

2.5 DETECTING ERRORS IN DATA TRANSMISSION

How can devices check whether data arrived correctly? In this lesson you will learn three ways a receiving device can find out if data changed on its journey.

Key idea: data is stored and transmitted as binary (0s and 1s).

2.5 | Detecting errors

START WITH WHAT WE ALREADY KNOW

Data uses binary

Computers represent data using 0s and 1s.

Data travels between devices

A phone may send a message to a server, or one computer may send a file to another.

Important question: how can the receiver know that the bits arrived exactly as they were sent?

2.5 | Detecting errors

WHY CAN ERRORS HAPPEN?

Data transmission is not always perfect.

Data can be lost

Some bits or pieces may not arrive.

Data can be added

Extra or unwanted data may appear.

Data can change

A 0 may arrive as 1, or a 1 as 0.

Interference during transmission can cause these errors.

2.5 | Detecting errors

WHY DOES ACCURACY MATTER?

Incorrect data can cause real problems.

Password

If it arrives incorrectly, a user may not be able to log in.

Email address

If the address changes, an email may not reach the right person.

Order details

Incorrect details may stop a person receiving the product or service they ordered.

Devices need a way to detect transmission errors so action can be taken.

2.5 | Detecting errors

THREE ERROR DETECTION METHODS

Each method checks data after it has been transmitted.

1Parity check

Adds an extra bit to each byte to check whether the number of 1s is odd or even.

2Checksum

Calculates a value from the data and checks the value after transmission.

3Echo check

Sends the received data back so it can be compared with the original.

All three methods help detect errors. They do not all work in the same way.

Errors | Parity check | the basic idea

PARITY CHECK: THE BASIC IDEA

A byte in this method contains 7 data bits + 1 parity bit.

PParity bit
1Data bit

Parity setting

Errors | Parity check | odd and even

ODD PARITY AND EVEN PARITY

Count the number of 1s in the 7 data bits.

ODD PARITY

The total number of 1s, including the parity bit, must be odd.

Example: 2 data 1s → add parity bit 1 → total = 3 (odd).

EVEN PARITY

The total number of 1s, including the parity bit, must be even.

Example: 2 data 1s → add parity bit 0 → total = 2 (even).

Remember: the parity bit is chosen to make the total number of 1s match the selected rule.

Errors | Parity check | try it

BUILD THE PARITY BIT

Choose odd or even parity, then touch the data bits.

Errors | Parity check | detecting an error

HOW DOES A PARITY CHECK DETECT AN ERROR?

1. Send

The sender adds a parity bit to each byte.

2. Receive

The receiver counts the 1s in the byte it gets.

3. Check

If the count breaks the odd/even rule, an error is detected.

Errors | Parity check | a limitation

A LIMITATION OF PARITY CHECKS

If an even number of bits change, the parity count may still look correct. Watch what happens.

CAN AN ERROR HIDE?

19 Can you think of an instance in which an error could occur in the data, but this would not be detected by a parity check?

Answer: yes, when an even number of bits change.
Reason: the receiver only counts the 1s. If two bits change, the count stays odd or even, so the check still passes.
Example (even parity): sent 10111011 (six 1s) and received 00111010 (four 1s). Two bits are wrong, but the count is still even, so the error is not detected.
Errors | Checksum | the basic idea

CHECKSUM: THE BASIC IDEA

A checksum is a calculated value used to help check data.

1. Calculate

Before sending, calculate a value from the data.

2. Send together

Attach the checksum value to the data being transmitted.

3. Recalculate

The receiver calculates a new checksum from the received data.

If the two values match, no error is detected. If they do not match, an error is detected. A method such as modulus 11 can be used to calculate the checksum.

Errors | Check digit | how it works

HOW A CHECK DIGIT WORKS

  1. A number is entered or scanned.
  2. The system calculates what the check digit should be.
  3. It compares this with the check digit that came with the number.
  4. If they do not match, it detects a possible error.
  5. The data may be rejected and checked again.

Types of encryption

TWO TYPES OF ENCRYPTION

SYMMETRIC

Same key to encrypt and decrypt.

Example: one key locks and unlocks a box.

ASYMMETRIC

Two different keys: a public key and a private key.

Example: anyone can lock a box with Juma's public key, but only Juma's private key opens it.

Memory aid: Symmetric = Same key. Asymmetric = Two different keys.
